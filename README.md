# StartWork

Корпоративный веб-сервис адаптации новых сотрудников по внутренним материалам компании.

Основной сценарий: загрузка инструкции → извлечение текста → генерация черновика курса → проверка наставником → публикация → назначение новичку → прохождение → результаты наставнику.

Подготовлены обследование, модель объекта и план первой итерации. Текущий этап — организация разработки прототипа. План КТ-5: 09–18.11.2026; общий ориентир завершения проекта — 18.12.2026. Календарь согласовываем в KAN-22, требования — в KAN-23.

## Работа с Git

- main хранит стабильное состояние.
- На каждую задачу создается ветка feature/KAN-4-document-upload, fix/KAN-номер-название или docs/KAN-номер-название.
- Пример коммита: KAN-4: добавлено извлечение текста инструкции.
- В pull request указываются ссылка на задачу, выполненные требования, проверка и ограничения.
- Перед объединением изменения проверяет другой участник. Прямое изменение main при первоначальном оформлении репозитория — разовая инициализация.
- Секреты, реальные корпоративные документы и персональные данные в репозиторий не добавляются; для прототипа используются тестовые материалы.

## Структура и запуск

Начальная структура подготовлена в ветке `chore/KAN-24-project-bootstrap`, [PR #1](https://github.com/plasticCCM/startwork/pull/1).

- `backend/` — HTTP-каркас и тесты.
- `frontend/` — клиентская часть.
- `infra/` — среда разработки.
- `docs/` — проектная документация.

Нужен Python 3.11 или новее. Внешние библиотеки для каркаса не требуются.

```
git clone https://github.com/plasticCCM/startwork.git
cd startwork
git switch chore/KAN-24-project-bootstrap
python backend/app.py
```

Проверка доступности: http://127.0.0.1:8000/health. Остановка — Ctrl+C.

```
python -m unittest discover -s backend -p "test_*.py" -v
```

Сейчас доступен только технический маршрут `/health`. Основные функции прототипа запланированы в KAN-4–KAN-8.
Правила веток и проверки изменений — в [CONTRIBUTING.md](CONTRIBUTING.md).
