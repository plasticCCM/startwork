# StartWork

Корпоративный веб-сервис адаптации новых сотрудников по внутренним материалам компании.

Основной сценарий: загрузка инструкции → извлечение текста → генерация черновика курса → проверка наставником → публикация → назначение новичку → прохождение → результаты наставнику.

## Работа с Git

- main хранит стабильное состояние.
- На каждую задачу создается ветка feature/KAN-4-document-upload, fix/KAN-номер-название или docs/KAN-номер-название.
- Пример коммита: KAN-4: добавлено извлечение текста инструкции.
- В pull request указываются ссылка на задачу, выполненные требования, проверка и ограничения.
- Перед объединением изменения проверяет другой участник. Прямое изменение main при первоначальном оформлении репозитория — разовая инициализация.
- Секреты, реальные корпоративные документы и персональные данные в репозиторий не добавляются; для прототипа используются тестовые материалы.

## Подготовка среды

1. Клонировать репозиторий: git clone https://github.com/plasticCCM/startwork.git
2. Выбрать задачу Jira и создать ветку с ее номером.
3. Подтвердить версии и зависимости в задаче архитектуры до реализации. Предварительный стек: React/TypeScript, Python/FastAPI, PostgreSQL.
4. Добавлять зависимости, пример настроек без секретов и проверенные инструкции запуска вместе с первым работающим компонентом.

Команды запуска приложения появятся после реализации. Сейчас запускаемого сервиса и установленного набора зависимостей нет.

## Запуск приложения

Рабочее приложение находится в папке [application](application/). Разделы выше сохранены как исходные материалы планирования; инструкция ниже относится к добавленной реализации.

### Windows / PowerShell

Требуется Python 3.12 или новее и Git. В PowerShell выполните:

```powershell
git clone https://github.com/plasticCCM/startwork.git
cd startwork/application
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Если репозиторий уже скачан, обновите его командой `git pull` в ветке `main`, затем перейдите в `application` и запустите скрипт. При первом запуске скрипт создаст виртуальное окружение, установит зависимости и скопирует `.env.example` в `.env`. Для повторной установки зависимостей используйте `.\start.ps1 -Install`.

Откройте **http://127.0.0.1:8000**. Остановка сервера — **Ctrl+C**. Другой порт: `.\start.ps1 -Port 8002`.

### Linux / macOS или ручной запуск

Из папки `application` выполните (требуется Python 3.12+):

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Команду `cp` выполняйте только при первой настройке, чтобы не перезаписать свой ключ.

### Настройка генерации и базы

В локальном файле `application/.env` укажите ключ **ChatAnywhere**:

```dotenv
DEEPSEEK_API_KEY=ваш_ключ
DEEPSEEK_URL=https://api.chatanywhere.org/v1/chat/completions
DEEPSEEK_MODEL=deepseek-v4.1-flash
DATABASE_URL=
```

Модель должна быть доступна вашему ключу; при необходимости измените `DEEPSEEK_MODEL`. Без API-ключа можно собирать курсы вручную. При генерации текст материалов передаётся провайдеру. Ключ храните только в локальном `.env`, не добавляйте его в Git.

`DATABASE_URL` можно оставить пустым: SQLite создаётся автоматически в `application/data/startwork.db`. Отдельный сервер базы для локального запуска не требуется. Настройка PostgreSQL и ограничения описаны в [подробной инструкции](application/README.txt).

### Первый сценарий

1. Зарегистрируйте наставника: логин и пароль хотя бы с одной цифрой; почта необязательна.
2. Создайте курс, загрузите материалы или вставьте текст.
3. Подготовьте черновик с ИИ либо добавьте темы вручную; проверьте задания и опубликуйте курс.
4. Зарегистрируйте обучающегося отдельным аккаунтом и назначьте ему курс из кабинета наставника.
5. Пройдите обучение под аккаунтом обучающегося; результаты доступны наставникам этого курса.

Приглашённый наставник получает доступ после принятия приглашения. Удаление курса доступно только создателю и требует ввода названия для подтверждения.
