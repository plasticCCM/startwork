# Порядок разработки StartWork

Связанная организационная задача: [KAN-24](https://mloga43v.atlassian.net/browse/KAN-24).
Рабочие требования и их согласование: [KAN-23](https://mloga43v.atlassian.net/browse/KAN-23).

1. Выбрать свою задачу Jira; проверить результат, FR/NFR, оценку, срок и зависимости.
2. Создать ветку от актуальной main: feature/KAN-4-document-upload, fix/KAN-номер-описание или chore/KAN-24-project-bootstrap.
3. Включать номер KAN в сообщение каждого коммита. Не приписывать изменения другому участнику.
4. Открыть pull request в main. Указать Jira, требования, результат, проверки и ограничения.
5. Передать проверку другому участнику. Не считать собственный PR независимой проверкой.
6. После устранения замечаний и одобрения объединить изменения; приложить ссылку к Jira и подтвердить критерии Done.

main — стабильная ветка. Защита ветки и обязательный review технически пока не настроены: это командный регламент.
Аккаунты GitHub остальных участников нужно добавить после получения их имен; нельзя заменять их авторство учетной записью владельца.

## Начальная структура и запуск

- backend/ — запускаемый технический каркас, только GET /health.
- frontend/ — место будущего интерфейса.
- infra/ — решения по среде; развертывание еще не подготовлено.
- docs/ — навигация по проектным материалам.
- .github/ — шаблон проверки изменений.

Для каркаса нужен Python 3.11+; внешних библиотек нет. Из корня:
```
python backend/app.py
```
Открыть http://127.0.0.1:8000/health. Остановить Ctrl+C.
Проверка:
```
python -m unittest discover -s backend -p "test_*.py" -v
```
Каркас проверяет готовность локальной среды и HTTP-обработчик. Он не реализует загрузку документов, генерацию, учетные записи, БД или обучение и не закрывает KAN-4..KAN-8.
Будущий стек React/TypeScript, FastAPI и PostgreSQL требует подтверждения при архитектурном проектировании.
